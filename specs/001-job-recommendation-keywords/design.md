# Design: 초기상담 도우미 (가칭) 화면 설계

**Feature**: `001-job-recommendation-keywords` | **작성일**: 2026-10-10 | **상태**: Draft
**기준 문서**: `spec.md`, `design-brief.md`, `.specify/memory/constitution.md` (v2.0.0)
**기준 시안**: Claude Design 프로젝트 "초기상담 도우미 메인 페이지 시안 (A/B)"의 `시안 A - 서비스 프로토타입 v3.html`
(원본 `시안 A - 서비스 프로토타입.html`과 `v2`는 보존되어 있으며 기준이 아니다)

> **문서화 원칙**: 이 문서는 시안 v3의 실제 구조와 값을 기록한다. 시안에서 확인할 수 없는 값은
> "확인 필요"로 표시하고 추측하지 않는다. 시안은 소스를 읽어 문서화했고 화면으로 렌더링해 확인하지는
> 못했다. 따라서 렌더링 결과로만 알 수 있는 값은 모두 "확인 필요"이다.
> 이 문서에는 React 코드와 CSS 코드를 포함하지 않는다.
>
> **확인 필요 (승인 대상)**: 사용자가 "승인한" 시안이 v3인지 확인되지 않았다. v3가 최신본이라 기준으로 삼았다.

## 1. 디자인 콘셉트와 목표

**콘셉트**: 흩어진 이력 조각(학력, 경력, 자격증, 강점)이 얇은 선으로 연결되어 하나의 직무(추천 직업)로
이어지는 흐름. 메인에서는 어두운 네이비 Hero 위에서 이 흐름을 시각 요소로 보여주고, 내부 화면에서는
같은 구조를 "입력 항목 태그 → 추천 근거"로 이어지는 정보 구조로 옮긴다.

**목표**

1. 상담사가 첫 화면에서 서비스 목적(추천 직업 3개 + 자기소개서 키워드 3개)과 시작 방법을 이해한다. (FR-012, FR-014)
2. 결과의 모든 항목이 입력 항목과 연결되어 있음을 시각적으로 확인할 수 있다. (FR-013, 원칙 II)
3. 구직자가 함께 보아도 위축되지 않는 쉬운 말과 차분한 표현을 쓴다. (FR-019, 원칙 XII)
4. 데스크톱, 태블릿, 모바일에서 입력 → 결과 확인 → 복사/인쇄가 끝까지 된다. (FR-028, 원칙 XIV)
5. 키보드와 화면 낭독기로 모든 주요 행동을 수행할 수 있다. (FR-027, 원칙 XIII)

**대상 사용자**: 주 사용자 상담사, 간접 사용자 구직자(결과 화면을 함께 봄). 사용자 유형은 하나이다. (spec 사용자 절)

제목 "상담 중 이렇게 이용해요", 부제 "입력부터 검토까지, 상담 흐름을 끊지 않는 네 단계입니다."

## 3. 세 핵심 화면의 정보 구조

### 3.1 메인 페이지 (`data-view=main`)

1. Header (서비스 이름, 이용 방법)
2. Hero: 상단 라벨, 메인 문구, 보조 문구, CTA 2개, 참고용 안내문, 개인정보 안내문, 오른쪽 시각 요소
3. 이용 흐름 섹션 (`#flow`): 4단계 카드
4. 시작하기 전에 확인해 주세요 (NOTICE): 참고용 안내문, 개인정보 안내문, 주 CTA 반복
5. 푸터

### 3.2 구직자 정보 입력 페이지 (`data-view=input`)

1. Header, Page Header (kicker "STEP 01 · 입력", 제목, 부제)
2. 오류 요약 영역 (오류가 있을 때만 표시)
3. 섹션 목차(데스크톱) + 입력 섹션 5개: 기본 정보 / 경력 / 인턴 경험 / 자격증·교육이수 / 강점 3개
4. 하단 고정 바: 필수 항목 진행 텍스트 + "결과 생성하기"

### 3.3 결과 페이지 (`data-view=result`)

1. 상단 고정 참고용 안내 바 (두 줄 안내문)
2. Page Header (kicker "STEP 03 · 결과 확인", 제목 "상담 참고 결과", 부제)
3. 재생성 안내(재생성 직후에만)
4. 행동 버튼 바 + 상태 알림 영역
5. 입력 정보 요약 (접기/펼치기)
6. 영역 A: 취업 가능성이 높은 추천 직업 3개
7. 영역 B: 자기소개서 키워드 3개
8. "확인 필요" 범례, 하단 참고용 안내문

**시안에 있는 부가 화면**: 분석 중, 빈 화면, 생성 실패, 시간 초과, 요청 제한, 인쇄 미리보기. (14절, 15절)
구현 계획에서 추가한 상태: 형식 오류(생성 실패의 한 종류, 14절). 시안에 없다.

> **제외 대상**: 시안 맨 위의 검은 "시안 도구" 띠(화면 이동 버튼, 예시 입력 채우기, 실패·지연 시뮬레이션
> 체크박스)는 프로토타입 확인용이며 제품 UI가 아니다. 구현하지 않는다.
> **인쇄 미리보기 화면**도 구현하지 않는다. 인쇄는 결과 화면의 `@media print` 스타일과 브라우저 인쇄로 처리한다(plan, spec에 미리보기 화면 요구 없음). 15절의 미리보기 설명은 인쇄 시트의 모양 기준으로만 쓴다.
> **"상담 이력으로 저장" 버튼**은 구현 1단계에서 비활성으로 표시하고 "상담 이력 저장은 아직 준비 중이에요"를 글자로 안내한다. 로그인·저장은 2단계(spec Assumptions)이다.

## 4. 화면별 레이아웃

| 화면 | 데스크톱 (≥1101px) | 태블릿 (768~1100px) | 모바일 (≤767px) |
|------|--------------------|---------------------|-----------------|
| 메인 Hero | 2열: 문구 열 + 560px 시각 요소 | 1열: 문구 아래 시각 요소 가운데 | 1열: 시각 요소 대신 2×2 카드 + "연결" 구분선 + 직업 카드 |
| 이용 흐름 | 4열 + 화살표(→) | ≤1023px 2열, 화살표 숨김 | 1열 세로 타임라인 |
| 입력 | 좌 목차(230px, ≤1100px는 190px) + 우 폼 | 목차 190px + 폼 | 목차 없음, 접이식 섹션 |
| 결과 카드 | ≥1200px 3열 / ≤1199px 1열 | 1열 | 1열 |
| 인쇄 미리보기 | 794px 시트를 화면 폭에 맞춰 축소 | 동일 | 동일 |

- 최대 콘텐츠 폭은 1176px이다. 긴 설명문은 `max-width`(34~40em)로 줄 길이를 제한한다. (19절)
- **확인 필요**: 1440px, 1024px, 390px에서의 실제 렌더링. 소스상 1024px는 Hero 1열, 이용 흐름 4열, 입력 목차 190px, 결과 카드 1열이다.

## 5. 화면 간 이동

```
메인 ──[상담 시작하기]──▶ 입력 ──[결과 생성하기]──▶ (오류 있음) 오류 요약 + 필드 오류 ──▶ 수정 ──▶ 다시 제출
                                  │
                                  └─(오류 없음)──▶ 분석 중 ──▶ 결과
결과 ──[입력 수정하기]──▶ 입력(내용 유지) ──▶ 결과 생성하기 ──▶ 분석 중 ──▶ 결과(재생성 안내 표시)
결과 ──[다시 생성하기]──▶ 분석 중 ──▶ 결과(이전 결과를 교체했다는 안내 표시)
분석 중 ──(실패)──▶ 생성 실패 ──[다시 시도]──▶ 분석 중 ──▶ 결과
분석 중 ──(120초 초과)──▶ 시간 초과 ──[다시 시도]──▶ 분석 중
결과 ──[인쇄하기]──▶ 인쇄 미리보기 ──[결과로 돌아가기]──▶ 결과 / [인쇄하기] → 브라우저 인쇄
입력 없이 결과에 직접 진입 ──▶ 빈 화면 ──[구직자 정보 입력하러 가기]──▶ 입력
```

- 생성 실패, 시간 초과, 요청 제한에서 "입력 수정하기"로 입력 화면에 돌아갈 수 있다.
- **재생성이 실패하면 이전 결과는 표시하지 않는다**(FR-024). 이전 결과는 새 결과가 성공할 때만 교체된다.
- **분석 중에 뒤로 가기**: 요청이 중단되고 입력은 유지되며 결과는 표시되지 않는다. 분석 중에는 중복 제출이 불가능하다(spec Edge Cases).
- **경로 대응**: 시안의 해시 경로를 구현에서는 `#/main` → `/`, `#/input` → `/input`, 결과와 모든 상태 화면 → `/result`로 바꾼다(research 8절).
- 주소 해시(`#/main`, `#/input` 등)로 화면이 구분된다(시안 기준). 화면 전환 시 해당 화면 제목으로 포커스가 이동하고 문서 제목이 바뀐다. (22절)
- **확인 필요**: 요청 제한 화면으로 가는 실제 조건. 시안에서는 상단 도구 버튼으로만 열린다.
- **확인 필요**: 결과에서 입력 수정 후 "결과로 돌아가기" 경로는 없다.

관련: FR-010, FR-011, FR-021~024, 원칙 X.

## 6. 사용 맥락별 차이

시안에는 맥락별 전용 모드가 없다. 아래는 같은 화면이 맥락에 따라 어떻게 쓰이는지 기록한 것이다.

| 맥락 | 시안에서 확인되는 구성 |
|------|------------------------|
| 상담사 단독 사용 | 입력 화면의 섹션 목차 + 진행 상태, 하단 고정 바, 결과 화면의 입력 정보 요약(접힘), 복사하기 |
| 태블릿으로 구직자와 함께 보기 | 결과 카드 1열, 본문 17.5px, 줄 간격 1.75, 참고용 안내 바 상단 고정, "상담에서 함께 확인할 점" 영역 |
| 인쇄해서 전달 | 인쇄 미리보기(A4 한 장), 구직자 입력 정보와 입력 폼은 인쇄하지 않음, 흑백 구분 (15절) |

- **확인 필요**: 태블릿 전용 크기 조정(글자 확대 등)이 있는지. 소스상 태블릿 전용 규칙은 없고 일반 반응형 규칙만 있다.
- 결과 복사 텍스트에는 구직자 입력 정보가 포함되지 않는다. (상태 문구 "구직자 입력 정보는 포함되지 않아요", FR-021)

## 7. Header와 Navigation 규칙

- 구성: 왼쪽 로고 마크 + 서비스 이름(홈 링크), 오른쪽 "이용 방법" 링크 하나. **로그인·회원 영역 없음.**
- 메인에서는 Header가 Hero 위에 투명하게 겹친다. 내부 화면(입력, 결과, 상태 화면)에서는 어두운 네이비 배경(`#07111F`) 단색 막대이다.
- "이용 방법"은 어느 화면에서든 메인으로 이동한 뒤 이용 흐름 섹션으로 스크롤한다.
- 링크는 높이 44px 이상, 흰 글자, 반투명 테두리.
- "본문 바로가기" 링크가 문서 맨 앞에 있고 포커스될 때만 보인다.
- 현재 위치 표시용 전역 메뉴는 없다. 위치는 Page Header의 kicker와 입력 화면의 섹션 목차로 알린다.
- **확인 필요**: 로그인 이후 메뉴(상담 이력, 구직자 기록) 위치. 시안에 없다. (FR-030~035)

## 8. Page Header 규칙

- 구성: kicker(영문 대문자 모노스페이스 14px, 틸) → 제목(H1) → 부제(보조색, 최대 38em).
- kicker 문구: 입력 "STEP 01 · 입력", 결과 "STEP 03 · 결과 확인", 메인 이용 흐름 "HOW IT WORKS", 안내 "NOTICE".
- 제목은 화면 전환 시 포커스를 받는다(포커스 윤곽선은 숨김, 화면 낭독기가 제목을 읽음).
- 분석 중, 빈 화면, 실패, 시간 초과, 요청 제한 화면은 kicker 없이 상태 배지 + H1을 카드 안에 둔다.
- **확인 필요**: 분석 중이 STEP 02에 해당하지만 kicker가 없다.

## 9. 메인 Hero 구조

- 배경: 어두운 네이비 + 그라데이션 + 격자 (10절).
- 왼쪽(문구 열): 상단 라벨(테두리 박스) → H1 → 보조 문구 → CTA 행 → 참고용 안내(박스, 두 줄) → 개인정보 안내(한 줄, 아이콘 ▣).
- CTA 행: 주 CTA는 민트 배경 + 짙은 글자, 보조 CTA는 투명 + 흰 테두리. 높이 52px.
- 오른쪽(시각 요소): 이력 조각 카드 4장 + 추천 직업 카드 1장 + 연결선. 장식이므로 화면 낭독기에서 숨긴다.
- 모바일: 시각 요소 대신 2×2 이력 카드, "연결" 구분선, 직업 카드를 세로로 배치. CTA는 문구 바로 아래 전체 너비.
- Hero 아래는 밝은 Surface(`#F3F6F8`)로 전환된다. 이용 흐름 카드는 흰색.
- Hero 예시 데이터: "사회복지학 전공, 대졸 / 지역아동센터 생활지도 / 사회복지사 2급 / 상대의 이야기를 끝까지 듣는다 → 사회복지사 (복지기관 사례 관리)". 직업 카드에 "추천 직업 · 가상 예시" 표시. 이력 카드 4장 자체에는 "가상 예시" 표시가 없다. (**확인 필요**: 의도 여부)

## 10. Gradient, Grid Glow, 이력 조각 연결 Floating Card

**Gradient**: 네이비(`#07111F` → `#0B1B2E` → `#0B2A33`) 기본 + 오른쪽 아래 그린 광원(`#1B6B52` 65%) + 위쪽 틸 광원(`#0E5C63` 55%).

**Grid Glow**: 48px 간격 격자선, 흰색 4.5% 불투명도, 위에서 아래로 사라지는 마스크.

**이력 조각 카드**: 폭 210px, 최소 높이 72px, 반투명 네이비(`rgba(18,40,63,.92)`) + 1px 테두리, 반경 6px.
라벨(학력/경력/자격증/강점, 민트 13px)과 내용(15px). 위치는 왼쪽 두 줄로 어긋나게 배치.

**추천 직업 카드**: 폭 220px, 연회색 배경, 위쪽 4px 민트 선, 직업명 24px + 보조 설명.

**연결선**: SVG 선 4개(민트, 1.5px, 75% 불투명) + 양 끝 점. 점선(5·7)이 흐르는 애니메이션은 3회 반복 후 멈춘다.

**진입 모션**: 카드가 아래에서 떠오르며 나타남(0.7초, 카드별 지연 0.1~0.45초). 제목·보조 문구·CTA도 같은 방식.
모든 모션은 움직임 허용 설정에서만 동작하고, 기본 상태가 최종 화면이다. (23절, 원칙 XIII)

**강점 입력**: placeholder 예시 3개: "처음 보는 사람과도 대화를 편하게 이끈다", "맡은 일은 계획을 세워 끝까지 마무리한다", "상대의 이야기를 끝까지 듣는다".

- 데스크톱: 왼쪽 고정 목차. 섹션별 상태 아이콘(○ 미입력, ✓ 입력됨, ! 확인 필요)과 "(필수)/(선택)" 텍스트.
- 모바일: 섹션 제목이 접이식 버튼이고 오른쪽에 상태 텍스트("미입력", "✓ 입력됨", "! 확인 필요", "선택")와 화살표. 첫 섹션만 열림.
- 하단 고정 바: "필수 항목 N/4개 입력됨 · 저장하기를 누르기 전에는 저장되지 않습니다." + "결과 생성하기 →". 진행은 텍스트로만 표시하고 막대 그래프는 없다.

관련: FR-001~008, FR-037, 원칙 V, VI, XII, XIII.

## 13. 결과 페이지 구조

### 13.1 참고용 안내문 위치

- 화면 맨 위에 **상단 고정 바**(네이비 배경, 화면을 스크롤해도 남음): 두 줄 안내문(모바일에서는 줄바꿈될 수 있음).
- 맨 아래에도 같은 두 줄 안내문(흰 박스).
- 복사 텍스트와 인쇄물에도 같은 두 줄이 들어간다. (FR-016, 원칙 I, IV)

### 13.2 입력 정보 요약

- `접었다 펼칠 수 있는` 영역("입력 정보 요약", 기본 접힘). 항목: 나이, 최종학력, 전공, 경력, 인턴 경험, 자격증, 교육이수, 강점 3개.
- 데스크톱은 2열 정의 목록(항목명 140px + 내용), 모바일은 1열.

### 13.3 추천 직업 카드 (영역 A)

영역 A는 흰 배경, 위쪽 5px 틸 선, 왼쪽 "A" 칩, 제목 "취업 가능성이 높은 추천 직업 3개", 부제 "입력하신 이력과의 적합도를 기준으로 골랐고, 연결된 근거와 함께 보여드려요."
카드 안(연회색 배경, 순서):

1. "추천 직업 N" (모노스페이스 14px)
2. 직업명(24px 굵게) + 보조 설명(15.5px, 예: 복지기관 사례 관리)
3. (통용 직업명일 때만) 배지 "? 표준 분류 확인 필요" (FR-036)
4. "추천 근거" + 본문
5. "연결된 입력 항목" + 태그들 ("전공: 사회복지학", "자격증: …", "강점: …")
6. "상담에서 함께 확인할 점" 상자(왼쪽 네이비 4px 선, 흰 배경) — 시안에서 이전 "준비 상태"를 이 이름으로 바꿨다.

태그: 테두리 1px, 흰 배경, 반경 4px, 항목명은 굵은 틸 13px 뒤에 ":" 가 붙음.

### 13.4 자기소개서 키워드 카드 (영역 B)

영역 B는 `#E4ECF2` 배경, 위쪽 5px 네이비 선, 왼쪽 "B" 칩(네이비+민트), 제목 "자기소개서 키워드 3개". 카드(흰색):

1. "키워드 N" (+ 강점이 약할 때 "※ 상담에서 함께 보강해요" 태그)
2. 키워드(24px 굵게)
3. 정의 목록: "연결 강점", "연결 직업"
4. "연결된 입력 항목" Tag들 — **제안, v3에 없음, 승인 대기 T069**. 강점(`strength`)을 뺀 객관 항목(전공·경력·인턴·자격증·교육이수·학력)만 13.3의 Tag 형식(`항목명: 값`)으로 보인다. 연결된 객관 항목이 없으면(불일치 키워드) 이 영역을 만들지 않는다
5. "설명" 본문
6. (불일치 시) 안내 상자 (13.7)

**결정됨**: 라벨은 "연결 직업"으로 통일한다. spec FR-014를 이에 맞게 수정했다.

**영역 구분**: A는 흰색+틸, B는 청회색+네이비, 알파벳 칩 A/B, 제목, 카드 머리말("추천 직업 N" / "키워드 N")로 구분한다. 색에만 의존하지 않는다.

### 13.5 "확인 필요" 표기 방식

- 해당 문장을 노란 점선 상자(`#FFF3D6` 배경, `#C79A2E` 점선, 짙은 갈색 글자)로 감싸고, 앞에 배지 "? 확인 필요"(흰 배경, 갈색 글자, 사각 아이콘)를 붙인다.
- 하단 범례: "[? 확인 필요] 이 표시가 붙은 문장은 상담에서 직접 확인이 필요한 내용이에요."
- 복사 텍스트에서는 "[확인 필요] " 접두, 인쇄에서는 "[확인 필요]" 텍스트 + 왼쪽 이중선 + 이탤릭. (FR-017, 원칙 IV)

### 13.6 행동 버튼

한 줄 버튼 바: [결과 복사하기(주)] [인쇄하기] [상담 이력으로 저장] | [입력 수정하기] [다시 생성하기]. 높이 44px. 모바일에서는 2열로 줄바꿈된다.
바로 아래에 상태 알림 영역(`role=status`, `aria-live=polite`).

- "상담 이력으로 저장": 시안에서 동작하지 않고 "상담 이력 저장은 로그인 후 사용할 수 있어요. 이 시안에서는 동작하지 않습니다."를 표시한다. (FR-032)
  **확인 필요**: 저장 동작, 저장 후 상태, 로그인 필요 시 표시 방식.
- 재생성 직후에는 "새로 생성한 결과로 바꿨어요. 이전 결과는 더 이상 표시되지 않습니다." 알림 박스가 나타난다. (FR-024)

## 20. 버튼·입력창·카드·배지·태그 규칙

**버튼**
- 높이: 기본 52px, 작은 버튼 44px. 반경 6px, 굵기 600, 글자 17px(작은 버튼 16px). 아이콘은 `aria-hidden` 텍스트 글리프(→ ↻ ⧉ ⎙ ▤ ✎).
- 종류: 민트(어두운 배경 위 주), 고스트(어두운 배경 위 보조), 틸 채움(밝은 배경 주), 흰색 + 네이비 테두리(보조), 삭제(빨강 테두리), 추가(틸 점선 테두리).
- 비활성: 불투명도 55% + 금지 커서. 비활성 사유는 글자로도 알린다(예: "최대 N개까지 입력할 수 있어요").
- 모바일: CTA, 하단 고정 바 버튼, 상태 카드 버튼은 전체 너비.

**입력창**: 높이 48px 이상, 테두리 1.5px `--field`, 반경 6px, 글자 17px. 포커스 시 3px 윤곽선. 오류 시 빨강 2px 테두리. 비활성은 점선 + 연회색.
**선택 상자**: 입력창과 동일하되 오른쪽 화살표. **체크·라디오**: 높이 48px 박스형, 선택되면 연한 틸 배경 + 틸 테두리.

**카드**: 흰 배경(영역 A 안의 직업 카드는 `--surface`), 1px `--rule` 테두리, 반경 6px, **그림자 없음**. 하단 고정 바와 인쇄 시트만 얕은 선/그림자를 쓴다.
**상태 배지**: 높이 36px, 반경 4px, 1.5px 테두리, 왼쪽 정사각 아이콘 칩 + 텍스트. 종류: 진행(틸), 실패(빨강), 경고(노랑), 정보(파랑).
**태그/칩**: 반경 4px, 1px 테두리, 흰 배경, 항목명(굵은 틸 13px) + ":" + 값(15px).
**확인 필요 배지**: 반경 3px, 갈색 글자, 노란 테두리, 왼쪽 갈색 정사각 칩에 "?".

반경은 4~6px로 통일한다(과도한 둥근 모서리 금지). 원형은 안내 아이콘(i), 번호 칩 등 작은 요소에만 쓴다.

## 22. 키보드 포커스와 접근성

- **포커스 표시**: 모든 상호작용 요소에 3px 윤곽선(밝은 배경 `#0B1B2E`, Header·Hero 위 `#FFD166`), 오프셋 2~3px. 포커스된 입력창은 윤곽선 + 테두리 색 변화.
- **키보드**: 모든 링크와 버튼은 실제 `a`/`button`이고 Tab 순서는 화면 순서이다. "본문 바로가기" 링크가 있다. 오류 요약 링크는 해당 입력창으로 포커스를 옮긴다.
- **화면 전환**: 제목(H1)으로 포커스 이동, 문서 제목 갱신.
- **화면 낭독기 알림**: 오류 요약(`role=alert`), 분석 중 단계(`role=status`), 지연 안내(`role=status`), 복사 완료·실패·저장 안내(`aria-live=polite`), 생성 실패·시간 초과·요청 제한 카드(`role=alert`).
- **색상 외 표시**: 상태 배지, 입력 오류, 섹션 상태, "확인 필요", 필수/선택이 모두 아이콘과 텍스트를 함께 쓴다.
- **터치 영역**: 버튼, 선택 상자, 체크·라디오, 목차 링크, 접이식 섹션 제목 모두 44px 이상. 오류 요약 링크도 44px.
- **대비 (토큰 값으로 계산, 렌더링 미확인)**: WCAG 상대 휘도 공식으로 16절 토큰 쌍을 계산했다. 일반 글자 4.5:1, UI 경계 3:1 기준 모두 통과한다.

| 조합 | 대비 | 조합 | 대비 |
|------|------|------|------|
| ink / surface | 15.98 | white / teal-700 (버튼) | 7.69 |
| ink / card | 17.35 | mint-ink / mint (Hero CTA) | 9.28 |
| muted / surface | 7.25 | white / navy-950 | 18.94 |
| muted / card | 7.86 | mint / navy-950 | 11.60 |
| teal-800 / surface | 9.18 | mint / navy-800 (이력 카드) | 9.18 |

| muted / 영역 B 배경 | 6.58 | need-ink / need-bg | 7.92 |
| teal-800 / 영역 B 배경 | 8.34 | soft-ink / soft-bg | 10.73 (불일치 안내 글자 `#0F2748`은 12.91) |
| 성공 `#14502B` / card | 9.49 | 입력창 테두리 field / card (UI 3:1) | 4.12 |
| 포커스 윤곽 focus-light / surface | 15.98 | 포커스 윤곽 focus-dark / navy-950 | 13.13 |

  - 카드 테두리 `--rule`(#CBD5DF)은 흰 배경 대비 1.49이다. 카드 경계는 장식이며 내용과 제목으로 식별되므로 3:1 요구 대상으로 보지 않는다(**확인 필요**: 검토자 판단).
  - 비활성 요소(불투명도 55%)는 WCAG 대비 요구의 예외이나, 비활성 사유를 글자로 알린다(20절).
  - 반투명 배경 위 글자(Hero 이력 카드 `rgba(18,40,63,.92)`)와 그라데이션 위 글자는 계산하지 않았다. 렌더링 후 측정이 필요하다.
- **터치 영역 간격**: 인접한 클릭·터치 대상 사이는 8px 이상을 둔다(제안, 시안 값은 확인 필요).
- **낭독기 알림 우선순위**: 즉시 알려야 하는 것(`role=alert`, assertive)은 오류 요약, 생성 실패·시간 초과·요청 제한·형식 오류 카드이다. 차분히 알리는 것(`role=status`/`aria-live=polite`)은 분석 중 단계, 지연 안내, 복사 완료·실패, 저장 안내, 재생성 알림, 지시문·강점 중복 경고이다.
- **읽는 순서**: 입력창은 라벨 → "(필수)/(선택)" → 힌트 → 글자 수 → 오류 순으로 `aria-describedby`에 연결한다.
- **화면 전환**: 메인, 입력, 결과와 모든 상태 화면(분석 중, 빈 화면, 생성 실패, 형식 오류, 시간 초과, 요청 제한)에서 H1으로 포커스가 이동하고 문서 제목이 바뀐다.
- **장식**: Hero 시각 요소는 `aria-hidden`이고 같은 정보가 결과 미리보기 예시에 텍스트로 있다.
- **확인 필요**: 모바일에서 아코디언 섹션의 Tab 이동, `scrollIntoView` 사용(시안 코드)이 앱 환경에서 문제가 없는지.

관련: FR-027, 원칙 XIII.

## 23. prefers-reduced-motion 규칙

- 모든 장식 애니메이션은 "움직임 허용" 설정에서만 동작하고, 기본 상태가 최종 화면이다. (카드 떠오름, 선 흐름, 화면 전환 페이드, 회전 아이콘, 부드러운 스크롤)
- 연결선 흐름은 무한 반복이 아니라 3회 후 멈춘다.
- 분석 중 단계 진행 간격: 일반 1초, 움직임 감소 설정 0.7초. 단계 상태는 "완료/진행 중/대기" 텍스트로 표시하므로 회전 아이콘이 멈춰도 정보가 유지된다.

- **결정됨**: 움직임 감소 설정에서는 페이드로 대체하지 않고 **정지하며 최종 상태를 바로 보여준다**(시안 동작 유지).
- **원칙**: 모션은 정보 전달 수단이 아니다. 모든 모션을 끄고도 같은 정보를 글자로 읽을 수 있어야 한다(FR-027, 원칙 XIII).

## 24. 문구 톤 규칙

시안에서 쓰는 톤: 해요체, 짧은 문장, 안내와 제안 중심("~해 보면 좋아요", "함께 확인해요").
구직자 평가나 부족을 단정하지 않고 "상담에서 함께 확인할 점", "이야기를 더 나눠 보면 좋아요"로 표현한다.

## 26. 구현 후 시각 검증 항목

각 항목은 구현 화면에서 예/아니오로 확인한다.

**메인**
