# Feature Specification: 추천 직업 및 자기소개서 키워드 생성

**Feature Branch**: `001-job-recommendation-keywords`

**Created**: 2026-10-10

**Status**: Draft

**Input**: User description: "직업상담사가 구직자 초기대면상담 중에 사용하는 '추천 직업 및 자기소개서 키워드 생성' 기능을 명세해줘. 기술 스택은 다루지 말고 무엇을, 왜 만드는지에 집중해줘."

## 배경과 목적

초기상담 시간은 짧은데, 구직자의 이력을 빠르게 정리해 방향을 잡아주기 어렵다. 이 기능은 상담사가 구직자 정보를 입력하면 추천 직업과 자기소개서 키워드를 즉시 제시해 (1) 상담의 출발점을 만들고, (2) 구직자가 자기 강점을 직무 언어로 표현하도록 돕는다.

**사용자**: 주 사용자는 입력과 결과 해석을 맡는 직업상담사이며, 간접 사용자는 상담 중 결과 화면을 함께 보는 구직자이다. 상담사는 로그인해서 사용하며, 상담 이력과 구직자 기록은 로그인한 상담사 본인의 것으로 저장·조회된다. 관리자 등 별도 역할 구분은 없다(MVP).

## Clarifications

### Session 2026-10-10

- Q: 나이를 정확한 숫자로 받고 추천 결과 생성에는 사용하지 않을까? → A: 정확한 숫자로 입력받되 추천 생성에는 전달하지 않고, 화면 표시와 상담 이력 저장에만 사용한다.
- Q: "취업 가능성이 높은 직업" 표현을 어떻게 다룰까? → A: 결과 화면에서 "취업 가능성이 높은" 표현을 그대로 사용하되, 추천은 입력 정보와의 적합도에만 근거하며 시장 수요 데이터는 쓰지 않는다는 한계를 안내문으로 알린다.
- Q: 추천 직업명은 표준 분류 직업명으로 제한할까? → A: 한국고용직업분류의 직업명을 우선 사용하고, 정확히 맞는 이름이 없으면 통용되는 직업명을 쓰되 "표준 분류 확인 필요"로 표시한다.
- Q: 입력 항목별 최대 글자 수와 복수 입력 최대 개수는? → A: 강점 1개와 직무명·업종·전공·자격증명·과정명은 각 100자, 인턴 내용은 400자. 경력·자격증·교육이수는 각 20개, 전공은 6개까지.
- Q: 결과 생성 대기 시간이 길어질 때 안내 방식과 제한 시간은? → A: 진행 문구를 표시하고 30초 후 지연 문구로 바꾸며, 120초에 중단하고 입력을 유지한 채 재시도를 안내한다.
- Q: 키워드 카드의 "연결 직무" 항목 이름은? → A: 추천 직업 중 하나를 가리키므로 "연결 직업"으로 통일한다(FR-014 수정).
- Q: 메인 보조 문구("잘 맞는 직업")와 결과 제목("취업 가능성이 높은 추천 직업")의 표현 차이는? → A: 의도한 차이로 둔다. 결과 제목은 FR-012와 안내문 한계 문구(FR-016)를 함께 쓴다.
- Q: 요청이 일시적으로 제한되는 상태를 명세에 넣을까? → A: 넣는다(FR-038). 생성 실패와 구분해 안내하고 재시도를 제공한다.

### Session 2026-10-11 (요구사항 품질 점검 `checklists/requirements-quality.md` 반영 — 작성자 제안, 사용자 승인 대기)

> 이 절의 항목은 사용자가 답한 clarify가 아니라 품질 점검에서 작성자가 정한 **제안 값**이다. `tasks.md` T069에서 항목별로 승인·수정·거절을 기록하며, 승인 전까지는 확정이 아니다. 아래 `Q → A`의 A는 제안 값이다.


- Q: "준비 상태 한 줄 코멘트"의 이름과 길이는? → A: 시안의 "상담에서 함께 확인할 점"으로 통일하고, 한 문장 120자 이내로 한다(FR-012). "준비 상태"는 쓰지 않는다.
- Q: 식별 정보 형식이 입력에서 감지되면? → A: 차단하고 해당 부분을 지우도록 안내한다(FR-009). 지시문 형태 입력은 차단하지 않고 경고하며 데이터로만 취급한다(FR-010).
- Q: 실패 유형별 안내는? → A: 연결·내부 오류는 "연결이 원활하지 않았어요", 형식 오류는 "결과 형식이 맞지 않아 보여드릴 수 없어요", 시간 초과·요청 제한은 각각 별도 문구를 쓴다(FR-020, FR-023, FR-038).
- Q: 서버와 화면의 시간 제한이 다를 때 시간 초과 표시는? → A: 화면은 120초에 중단하고, 서버가 먼저 중단해도 같은 "시간 초과" 상태로 보인다. 문구에는 구체 시간을 쓰지 않는다(FR-023).
- Q: 요청 제한의 기준과 재시도는? → A: 초기 기준은 같은 사용 환경에서 10분에 20회이며 운영 중 조정한다. 재시도는 바로 누를 수 있고 대기 시간 숫자는 보이지 않는다(FR-038).
- Q: 재생성이 실패하면 이전 결과는? → A: 표시하지 않는다. 재생성 결과는 이전과 달라질 수 있다(FR-024).
- Q: 대기 중 취소 버튼은? → A: 두지 않는다. 120초 제한으로 충분하다(FR-023).
- Q: 입력이 외부 AI 서비스로 전송됨을 알릴까? → A: 알린다(FR-039). 이름·연락처·나이는 전송하지 않는다.
- Q: 로그 정책을 요구사항으로 둘까? → A: 둔다(FR-040). 입력 본문, AI 응답 원문, 프롬프트는 로그에 남기지 않는다.
- Q: 중복된 강점은? → A: 입력 단계에서 같은 문장이면 경고한다(FR-041). 추상적 강점은 막지 않고 결과에서 구체화한다.
- Q: 키워드와 강점의 관계는? → A: 키워드 3개는 강점 3개를 하나씩 다룬다(FR-014, FR-015).
- Q: "확인 필요" 표시 조건은? → A: 입력만으로 단정할 수 없는 사실 문장에 표시한다(FR-017).
- Q: 인쇄 분량은? → A: 최대 길이 결과에서도 A4 한 장을 목표로 하며 넘으면 문장 길이 한도를 줄인다(FR-022).
- Q: 경력이 있는 구직자의 추천 직업은? → A: 추천 직업 중 1개 이상은 경력 항목과 연결한다(Edge Cases).
- Q: 입력 기간 칸의 한도와 나이 형식은? → A: 기간은 각 50자, 나이는 15~99 정수이다(FR-004, FR-037).
- Q: 키워드 카드에도 객관 항목 연결을 표시할까? → A: 표시한다. 강점 외에 연결된 객관 항목이 있을 때만 "연결된 입력 항목" Tag로 보인다(FR-013, FR-014, 원칙 II).

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 추천 직업과 키워드 확인 (Priority: P1)

상담사가 구직자의 필수 항목(최종학력, 경력, 나이, 인턴 경험, 강점 3개)을 입력하고 결과 생성을 누르면, 추천 직업 3개와 자기소개서 키워드 3개, 공통 안내문을 확인한다.

**Why this priority**: 이 기능의 핵심 가치이며, 이것만으로도 상담의 출발점을 제공하는 MVP가 된다.

**Independent Test**: 필수 항목만 채운 유효한 입력으로 결과를 생성해 직업 3개, 키워드 3개, 안내문이 표시되는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 필수 항목이 모두 유효하게 입력되어 있을 때, **When** 상담사가 결과 생성을 누르면, **Then** 추천 직업 정확히 3개(직업명, 추천 근거, "상담에서 함께 확인할 점" 한 문장)가 표시된다.
2. **Given** 같은 결과 화면에서, **When** 상담사가 키워드 영역을 보면, **Then** 키워드 정확히 3개(키워드, 연결된 강점, 연결된 추천 직업, 2~3문장 설명)가 표시된다.
3. **Given** 결과가 표시되었을 때, **When** 화면을 보면, **Then** "참고용 결과이며 상담사와 함께 검토가 필요하다"는 안내문이 표시된다.
4. **Given** 결과가 표시되었을 때, **When** 각 추천 근거를 확인하면, **Then** 모든 근거가 어떤 입력 항목(예: 전공, 경력, 자격증)과 연결되는지 명시한다.
5. **Given** 결과가 표시되었을 때, **Then** 취업률, 연봉, 채용 공고 수 등 검증되지 않은 수치가 없고, 확인이 필요한 정보는 "확인 필요"로 표시된다.

### User Story 2 - 입력 오류 안내 (Priority: P1)

입력이 누락되거나 잘못되면 상담사는 어떤 항목을 어떻게 고쳐야 하는지 안내받는다.

**Why this priority**: 입력 품질이 결과 품질을 좌우하며, 상담 중 막힘 없이 수정할 수 있어야 한다.

**Independent Test**: 필수 항목을 비우거나 비정상 값을 넣고 생성을 시도해, 항목별 안내가 표시되고 결과가 생성되지 않는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 필수 항목이 비어 있을 때, **When** 결과 생성을 누르면, **Then** 누락된 항목마다 항목명과 수정 방법이 안내되고 결과는 생성되지 않는다.
2. **Given** 강점이 3개가 아닐 때, **When** 결과 생성을 누르면, **Then** 정확히 3개를 입력해야 한다는 안내가 표시된다.
3. **Given** 나이에 숫자가 아닌 값이나 허용 범위를 벗어난 값이 있을 때, **When** 결과 생성을 누르면, **Then** 올바른 입력 방법이 안내된다.
4. **Given** 입력란에 AI에게 지시하는 문장이 있을 때, **When** 결과 생성을 누르면, **Then** 경고가 표시되고 그 문장은 지시로 실행되지 않으며 단순 입력 데이터로만 취급된다(FR-010). 허용 길이를 넘는 텍스트는 수정 안내가 표시되고 결과는 생성되지 않는다(FR-037).
5. **Given** 오류 안내가 표시된 상태에서, **When** 상담사가 항목을 고치면, **Then** 이미 입력한 다른 내용은 유지된다.

---

### User Story 3 - 결과 복사 및 인쇄 (Priority: P2)

상담사가 결과를 복사하거나 인쇄해 구직자에게 전달한다.

**Why this priority**: 결과를 상담 이후에도 활용하게 하는 기능이지만, 결과 생성 자체보다는 후순위이다.

**Independent Test**: 결과 생성 후 복사와 인쇄를 실행해 내용과 안내문이 모두 포함되는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 결과가 표시되어 있을 때, **When** 복사를 실행하면, **Then** 추천 직업, 키워드, 안내문이 읽을 수 있는 텍스트로 복사되고 복사 완료가 텍스트로 안내된다.
2. **Given** 결과가 표시되어 있을 때, **When** 인쇄를 실행하면, **Then** 결과와 안내문이 한 번에 읽기 좋게 출력된다.

---

### User Story 4 - 실패 시 재시도 (Priority: P2)

결과 생성에 실패하면 입력 내용이 유지된 채로 재시도할 수 있다.

**Why this priority**: 상담 중 실패로 재입력이 필요하면 상담 흐름이 끊긴다.

**Independent Test**: 생성 실패 상황을 일으킨 뒤 입력이 그대로이며 재시도로 결과를 얻을 수 있는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 결과 생성이 실패하거나 시간이 오래 걸릴 때, **When** 상태를 보면, **Then** 실패 또는 지연 상황이 쉬운 말로 안내되고 재시도 수단이 제공된다.
2. **Given** 실패 안내가 표시된 상태에서, **When** 상담사가 재시도를 누르면, **Then** 입력을 다시 하지 않고 결과 생성이 다시 시도된다.
3. **Given** 결과 형식이 요구 구조(직업 3개, 키워드 3개)를 충족하지 못할 때, **Then** 부분 결과를 표시하지 않고 오류로 안내한다.

---

### User Story 5 - 일부 수정 후 재생성 (Priority: P3)

상담사가 입력을 일부 수정한 뒤 결과를 다시 생성한다.

**Why this priority**: 상담이 진행되며 정보가 보완될 때 유용하나 첫 사용에는 필수가 아니다.

**Independent Test**: 결과 표시 후 입력 하나를 바꿔 재생성하면 새 결과로 교체되는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 결과가 표시된 상태에서, **When** 상담사가 입력 일부를 수정하고 다시 생성하면, **Then** 수정된 입력을 반영한 새 결과(직업 3개, 키워드 3개)가 표시된다.
2. **Given** 재생성 중일 때, **Then** 이전 입력은 유지되고 이전 결과와 새 결과를 혼동하지 않도록 현재 상태가 표시된다.

---

### User Story 6 - 상담사 로그인 (Priority: P1)

상담사가 로그인해 본인 계정으로 앱을 사용한다. 저장된 이력과 구직자 기록은 본인 계정에서만 접근할 수 있다.

**Why this priority**: 이력 저장과 구직자 기록은 계정 단위 접근 통제가 전제이며, 개인정보 보호 원칙의 기본 조건이다.

**Independent Test**: 로그인 전에는 기능과 저장된 데이터에 접근할 수 없고, 로그인 후 본인 데이터만 보이는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 로그인하지 않은 상태에서, **When** 앱에 접근하면, **Then** 로그인 화면이 표시되고 결과 생성과 저장 데이터는 사용할 수 없다.
2. **Given** 유효한 계정 정보로, **When** 로그인하면, **Then** 입력 화면으로 이동한다.
3. **Given** 잘못된 계정 정보로, **When** 로그인하면, **Then** 이유를 알 수 있는 안내가 표시된다.
4. **Given** 로그인 상태에서, **When** 로그아웃하면, **Then** 저장 데이터에 더 이상 접근할 수 없다.

---

### User Story 7 - 상담 이력 저장 및 조회 (Priority: P2)

상담사가 생성된 결과(입력 요약과 결과)를 상담 이력으로 저장하고, 이후 목록에서 다시 열어 본다.

**Why this priority**: 반복 상담과 후속 상담에서 가치가 크지만, 결과 생성 자체보다 후순위이다.

**Independent Test**: 결과를 저장한 뒤 이력 목록에서 같은 내용을 열어 보고, 다른 계정에서는 보이지 않는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 결과가 표시된 상태에서, **When** 상담사가 저장을 누르면, **Then** 입력 내용, 결과, 상담 일시가 이력으로 저장되고 저장 완료가 텍스트로 안내된다.
2. **Given** 저장된 이력이 있을 때, **When** 이력 목록을 열면, **Then** 일시 순으로 목록이 보이고 항목을 열면 저장 당시의 입력과 결과(안내문 포함)가 표시된다.
3. **Given** 저장된 이력이 있을 때, **When** 상담사가 삭제를 실행하면, **Then** 확인 후 해당 이력이 완전히 삭제된다.
4. **Given** 다른 상담사 계정으로 로그인했을 때, **Then** 이 상담사의 이력은 보이지 않는다.

---

### User Story 8 - 구직자 기록 관리 (Priority: P3)

상담사가 구직자별 기록(구직자 DB)을 만들고, 같은 구직자의 여러 상담 이력을 묶어서 본다.

**Why this priority**: 장기 상담 관리에 유용하지만 최소 가치(US1, US6, US7) 이후에 필요하다.

**Independent Test**: 구직자 기록을 만들고 상담 이력을 연결한 뒤 기록에서 이력을 확인한다.

**Acceptance Scenarios**:

1. **Given** 로그인 상태에서, **When** 새 구직자 기록을 만들면, **Then** 기록이 목록에 나타난다.
2. **Given** 구직자 기록이 있을 때, **When** 상담 이력을 저장하며 그 기록에 연결하면, **Then** 기록 화면에서 연결된 이력을 일시 순으로 볼 수 있다.
3. **Given** 구직자 기록이 있을 때, **When** 기록에서 새 상담을 시작하면, **Then** 이전 입력이 채워진 상태에서 수정 후 재생성할 수 있다.
4. **Given** 구직자 기록이 있을 때, **When** 삭제를 실행하면, **Then** 확인 후 기록과 연결된 이력이 함께 삭제된다.

### Edge Cases

- **신규 진입자**: 경력, 인턴, 자격증, 교육이수가 모두 없어도 결과가 생성되어야 하며, 이력 부재를 부정적 근거로 쓰지 않고 학력, 전공, 강점 등 있는 정보를 근거로 삼는다.
- **경력 공백이 긴 구직자**: 경력 공백은 별도 입력 항목이 아니며, 경력 기간 칸에 적은 내용이나 경력 사이의 간격으로만 드러난다. 공백을 이유로 직업을 배제하거나 부정적으로 평가하지 않고, 이전 경력과 강점 중심으로 근거를 제시한다(FR-018).
- **경력이 많은 중장년 전직 희망자**: 나이는 추천에 사용되지 않는다. 경력이 있는 구직자는 추천 직업 3개 중 1개 이상이 경력 항목과 연결되어야 한다.
- **추상적이거나 중복된 강점**(예: "성실함"): 추상적인 강점은 입력을 막지 않고 객관 이력과 연결해 구체화한다. 정규화 후 같은 문장인 강점은 입력 단계에서 경고해 상담사가 수정하도록 안내한다(FR-041).
- **강점과 객관 이력이 연결되지 않는 경우**: 연결되지 않는다는 사실을 비하 없이 안내하고, 어떤 정보를 더 확인하면 좋은지 제안한다(FR-015).
- **비정상 입력**(AI 지시문 삽입 등): 입력 단계에서 경고가 표시되고(FR-010), 지시로 실행되지 않으며 결과 구조와 안내문이 훼손되지 않는다.
- **식별 정보 형식 입력**(주민번호, 전화번호, 이메일 형식): 입력 단계에서 차단되고 지우도록 안내한다(FR-009).
- **고졸 이하**: 전공 입력 없이도 진행할 수 있다. 학력 수준과 상태의 조합은 제한하지 않는다.
- **"없음" 선택과 입력의 모순**: "경력 없음", "자격증 없음", "교육이수 없음"을 선택하면 해당 반복 입력은 비활성이 되며, 없음과 입력이 함께 유효한 상태로 제출되지 않는다(FR-003, FR-006, FR-007).
- **인쇄물 안내문 누락**: 복사와 인쇄 결과에도 안내문이 항상 포함된다.
- **생성 중 중복 제출**: 생성 중에는 같은 요청을 다시 보낼 수 없다(한 번에 하나).
- **생성 중 뒤로 가기**: 진행 중인 요청은 중단되고 입력은 유지되며 결과는 표시되지 않는다.
- **새로고침, 다른 탭**: 새로고침하면 입력과 결과가 사라지고 빈 화면이 표시된다. 탭끼리 상태를 공유하지 않는다(FR-025).

## Requirements *(mandatory)*

### Functional Requirements

**입력**

- **FR-001**: 시스템은 최종학력(고졸 이하/전문대/대졸/석사/박사)과 학력 상태(졸업/재학/휴학/중퇴/졸업예정)를 필수로 입력받아야 한다.
- **FR-002**: 시스템은 전공을 복수(주전공, 복수·부전공)로 선택 입력받아야 하며, 고졸 이하는 생략할 수 있어야 한다.
- **FR-003**: 시스템은 경력을 직무명, 업종, 기간의 반복 입력으로 받아야 하며, "경력 없음"을 선택할 수 있어야 한다. 경력 항목은 필수(없음 포함)이다. "경력 없음"을 선택하면 경력 입력은 비활성이 되고, 경력 없음과 경력 입력이 함께 있는 요청은 거부한다.
- **FR-004**: 시스템은 나이를 15~99 사이의 정수로 필수 입력받아야 한다. 입력된 나이는 화면 표시와 상담 이력 저장에만 사용하며, 추천 직업과 키워드를 생성하는 과정에는 전달하지 않아야 한다. 결과 생성 요청에는 나이를 포함하지 않으며(서버로도 보내지 않는다), 포함된 요청은 거부한다.
- **FR-005**: 시스템은 인턴 경험의 있음/없음을 필수로 입력받고, 있음일 때 내용과 기간을 입력받아야 한다.
- **FR-006**: 시스템은 자격증을 복수로 선택 입력받아야 하며 없음도 허용해야 한다.
- **FR-007**: 시스템은 교육이수 내용을 과정명과 기간의 복수 입력으로 선택 입력받아야 하며 없음도 허용해야 한다.
- **FR-008**: 시스템은 구직자가 생각하는 강점을 정확히 3개, 각 짧은 문장(공백 제외 2자 이상 100자 이내)으로 필수 입력받아야 한다. 비어 있는 강점은 칸마다 "강점 N을 입력해 주세요"로 안내한다.
- **FR-009**: 시스템은 주민번호 등 고유식별정보 입력란을 제공하지 않아야 하며, 프로필 입력(강점 등 자유 텍스트)에서 식별 정보 형식(주민등록번호, 전화번호, 이메일)이 감지되면 해당 입력을 차단하고 그 부분을 지우도록 해당 입력창에서 안내해야 한다. 형식이 비슷한 오탐은 상담사가 지우고 다시 입력한다. 구직자 기록의 식별 정보는 FR-029를 따른다.

**입력 검증**

- **FR-010**: 시스템은 필수 항목 누락, 비정상 값, 허용 길이 초과, 지시문 형태의 입력을 처리해야 하며, 문제가 있는 항목마다 항목명과 수정 방법을 안내해야 한다. 지시문 형태의 입력은 차단하지 않고 해당 입력창에 경고를 표시하며, 어떤 경우에도 지시로 실행하지 않고 데이터로만 취급한다. 문자열 입력은 앞뒤 공백을 제거하며 공백만 있는 입력은 비어 있는 것으로 본다.
- **FR-037**: 시스템은 입력 한도를 적용해야 한다. 강점 1개와 직무명, 업종, 전공, 자격증명, 과정명은 각 100자 이내, 인턴 내용은 400자 이내, 경력·인턴·교육이수의 기간은 각 50자 이내여야 한다. 경력, 자격증, 교육이수는 각 20개 이내, 전공은 6개 이내여야 하며, 한도를 넘으면 FR-010에 따라 안내해야 한다.
- **FR-011**: 시스템은 입력 오류가 있을 때 결과를 생성하지 않아야 하며, 이미 입력한 내용은 유지해야 한다.

**출력**

- **FR-012**: 시스템은 "취업 가능성이 높은 추천 직업"을 정확히 3개 제시해야 하며(추천 기준은 입력 정보와의 적합도이고 시장 수요·채용 데이터는 사용하지 않는다), 각각 직업명, 추천 근거(1~3문장), "상담에서 함께 확인할 점"(한 문장)을 포함해야 한다. 추천 근거와 확인할 점의 문장은 각각 120자 이내이다. 이 항목은 구직자를 평가하는 준비 상태가 아니라 상담에서 함께 이야기할 점으로 쓴다.
- **FR-036**: 추천 직업명은 한국고용직업분류의 직업명을 우선 사용해야 한다. 분류에 정확히 맞는 이름이 없으면 통용되는 직업명을 쓰고 해당 직업에 "표준 분류 확인 필요"를 표시해야 한다. 표준 여부는 AI가 판단해 표시하며 시스템이 분류표와 대조해 검증하지는 않는다(상담사가 확인하는 사항이다). 확실하지 않으면 "표준 분류 확인 필요"를 표시한다.
- **FR-013**: 모든 추천 근거는 연결되는 입력 항목을 명시해야 하며, 입력 항목과 연결되지 않는 추천은 표시하지 않아야 한다.
- **FR-014**: 시스템은 자기소개서 키워드를 정확히 3개 제시해야 하며, 각각 키워드, 연결되는 구직자 강점, 연결되는 추천 직업(추천 직업 3개 중 하나), 2~3문장의 설명(문장마다 120자 이내)을 포함해야 한다. 화면에서는 이 항목을 "연결 직업"으로 표기한다. 키워드 3개는 입력한 강점 3개를 하나씩 연결 강점으로 가져야 하며(같은 강점이 두 키워드에 연결되지 않는다), 강점 3개가 모두 다뤄진다. 키워드가 연결 강점 외에 객관 이력(전공, 경력 등)과도 연결되면 "연결된 입력 항목"으로 함께 표시한다(없으면 표시하지 않는다).
- **FR-015**: 시스템은 입력한 강점 3개를 모두 존중해 다루되, 객관 이력과 연결해 근거를 보강하고, 연결되지 않는 강점은 비하 없이 그 사실을 안내해야 한다. 객관 이력은 학력, 전공, 경력, 인턴, 자격증, 교육이수이며, 강점이 이 중 하나 이상을 연결 항목으로 가지면 연결된 것이고, 하나도 없으면 연결되지 않은 것이다. 연결되지 않은 강점에는 안내 문장이 반드시 있고, 연결된 강점에는 없어야 한다.
- **FR-016**: 시스템은 모든 결과 화면, 복사물, 인쇄물에 "참고용 결과이며 상담사와 함께 검토가 필요하다"는 안내문을 포함해야 한다. 안내문에는 추천이 입력된 이력과의 적합도에 기반하며 실제 채용 수요나 취업을 보장하지 않는다는 점도 함께 명시해야 한다. 안내문은 결과 제목("취업 가능성이 높은 추천 직업")이 있는 모든 위치(화면, 복사물, 인쇄물)에 두며, 모델이 아니라 시스템이 항상 붙인다.
- **FR-017**: 시스템은 취업률, 연봉, 채용 공고 수 등 검증되지 않은 수치를 결과에 포함하지 않아야 하며, 확인이 필요한 정보는 "확인 필요"로 표시해야 한다. 검증되지 않은 수치는 퍼센트, 금액, 연봉·급여·취업률·합격률·경쟁률·채용 공고 수 같은 통계 표현이다. 입력에 있던 값(예: "2급", "2년")을 그대로 옮겨 적는 것은 허용한다. "확인 필요"는 입력만으로 사실이라고 단정할 수 없는 문장(자격증이 요구되는 직무 범위, 업무 경험의 정도 등)에 붙인다. 직업명의 표준 분류 여부는 FR-036의 표시를 따른다.
- **FR-018**: 시스템은 나이, 학력, 경력 공백, 이력 부재를 이유로 직업을 배제하거나 부정적으로 평가하는 표현을 결과에 사용하지 않아야 한다.
- **FR-019**: 결과 문장은 구직자가 함께 보아도 이해할 수 있는 쉬운 말로 작성하고 낙인이나 위축을 주는 표현을 피해야 한다.
- **FR-020**: 요구 구조(직업 3개, 키워드 3개, 각 항목 필수 구성)를 충족하지 못한 결과는 표시하지 않고 오류로 안내해야 한다. 시스템은 구조를 충족하지 못한 결과에 대해 같은 입력으로 1회 다시 생성을 시도하며, 그래도 충족하지 못하면 부분 결과 없이 "결과 형식이 맞지 않아 보여드릴 수 없어요. 입력하신 내용은 그대로 남아 있습니다. 다시 시도해 주세요."와 같은 취지로 안내하고 재시도를 제공한다.

**상호작용**

- **FR-021**: 상담사는 결과를 복사하여 읽을 수 있는 텍스트로 가져올 수 있어야 하며, 복사 성공 여부가 텍스트로 안내되어야 한다. 복사물에는 구직자 입력 정보(나이, 학력, 이력 요약)를 넣지 않으며, 항목 구성과 형식은 `contracts/copy-and-print.md`를 따른다.
- **FR-022**: 상담사는 결과를 인쇄할 수 있어야 하며, 인쇄물에는 결과와 안내문이 읽기 좋게 포함되어야 한다. 인쇄물은 A4 용지 기준이며 글자 한도를 모두 채운 결과에서도 한 장에 들어가는 것을 목표로 한다(넘으면 문장 길이 한도를 줄인다). 흑백으로 인쇄해도 영역 구분, "확인 필요", 불일치 안내가 구분되어야 하고, 구직자 입력 정보와 입력 폼은 인쇄하지 않는다.
- **FR-023**: 결과 생성이 실패하거나 지연되면 쉬운 말로 상황을 안내하고 재시도 수단을 제공해야 하며, 입력은 유지해야 한다. 생성 중에는 진행 중임을 텍스트로 표시하고, 요청을 보낸 시점부터 30초가 지나면 지연 중임을 알리는 문구로 바꾸며, 120초가 지나면 생성을 중단하고 입력을 유지한 채 재시도를 안내해야 한다. 재시도하면 시간은 다시 0초부터 센다. 서버가 120초 전에 먼저 중단해도 같은 "시간 초과" 상태로 안내하며 문구에는 구체적인 시간을 쓰지 않는다. 연결 끊김 등 요청 자체의 실패도 "생성 실패"로 안내하고 재시도를 제공한다. 대기 중 취소 수단은 제공하지 않는다.
- **FR-038**: 시스템은 짧은 시간에 요청이 너무 많아 생성이 일시적으로 제한되면, 잠시 기다린 뒤 다시 시도하라는 안내와 재시도 수단을 제공하고 입력을 유지해야 한다. 이 상태는 생성 실패와 구분해서 표시한다. 초기 기준은 같은 사용 환경에서 10분에 20회이며 운영 중 조정할 수 있다. 재시도는 바로 누를 수 있고 대기 시간 숫자는 화면에 표시하지 않는다.
- **FR-024**: 상담사는 입력 일부를 수정한 뒤 결과를 다시 생성할 수 있어야 한다. 재생성한 결과는 같은 입력이라도 이전 결과와 달라질 수 있다. 재생성이 실패하면 이전 결과는 표시하지 않고 FR-023에 따라 안내한다.

**개인정보와 범위**

- **FR-025**: 시스템은 상담사가 저장을 명시적으로 실행하기 전에는 입력 데이터와 생성 결과를 서버와 브라우저 저장소(쿠키, 로컬·세션 저장소 포함) 어디에도 저장하지 않아야 한다. 입력과 결과는 화면이 열려 있는 동안 브라우저 메모리에만 유지되며, 새로고침하거나 화면을 닫으면 사라진다.
- **FR-026**: 시스템은 실시간 채용공고 연동, 자기소개서 전문 작성, 결과 공유 링크 생성 기능을 제공하지 않아야 한다.
- **FR-039**: 시스템은 입력한 이력이 결과를 만들기 위해 외부 AI 서비스로 전송된다는 사실을 입력 전에 화면에서 알려야 한다. 이름, 연락처, 나이는 전송하지 않는다는 점도 함께 안내한다. 외부 AI 서비스의 데이터 보관·학습 정책은 기관이 확인해야 할 사항이다.
- **FR-040**: 시스템은 구직자 입력 본문, AI 응답 원문, AI 요청 내용(프롬프트)을 어떤 로그에도 남기지 않아야 한다. 로그에는 요청 식별자, 처리 단계, 결과 코드, 소요 시간만 남긴다.
- **FR-041**: 시스템은 강점 3개 중 정규화(공백·문장 부호 제거) 후 같은 문장이 있으면 입력 단계에서 경고하고 서로 다른 강점을 적도록 안내해야 한다. 이 경고는 제출을 막지 않는다.

**로그인, 상담 이력, 구직자 기록**

- **FR-030** (2단계 구현. 1단계 배포에는 로그인이 없으므로 주소를 공개하지 않고 공급자 사용 한도로 보호한다): 시스템은 상담사 로그인과 로그아웃을 제공해야 하며, 로그인하지 않은 사용자는 기능과 저장 데이터에 접근할 수 없어야 한다.
- **FR-031**: 시스템은 저장된 이력과 구직자 기록을 소유한 상담사 본인만 조회, 수정, 삭제할 수 있게 해야 한다.
- **FR-032**: 상담사는 결과를 상담 이력(입력, 결과, 상담 일시)으로 저장하고, 이력 목록 조회와 상세 조회(안내문 포함), 삭제를 할 수 있어야 한다.
- **FR-033**: 상담사는 구직자 기록을 만들고, 상담 이력을 연결하며, 기록 단위로 이력을 조회하고 삭제할 수 있어야 한다. 삭제는 확인 후 연결된 이력까지 완전히 삭제해야 한다.
- **FR-034**: 상담사는 저장된 이력이나 구직자 기록에서 입력을 불러와 수정한 뒤 결과를 다시 생성할 수 있어야 한다.
- **FR-029**: 구직자 기록은 이름 등 최소한의 식별 정보(이름, 선택적으로 연락처)로 구분할 수 있어야 한다. 이 식별 정보는 구직자 기록에만 저장하며 주민번호 등 고유식별정보는 받지 않는다. 식별 정보는 추천 결과 생성 입력에 포함되지 않아야 한다.
- **FR-035**: 저장된 이력과 구직자 기록은 마지막 갱신일부터 1년이 지나면 자동으로 삭제되어야 하며, 상담사는 그 전에도 언제든 직접 삭제할 수 있어야 한다. 자동 삭제 기한은 기관 정책에 따라 조정할 수 있다.

**접근성과 사용 환경** (Constitution XIII, XIV)

- **FR-027**: 주요 행동(입력, 생성, 재시도, 복사, 인쇄, 오류 항목 이동, 접이식 섹션, 반복 입력 추가·삭제)은 키보드만으로 수행할 수 있어야 하고, 포커스가 3px 이상의 선으로 보여야 한다. 상태는 색상만이 아닌 텍스트와 아이콘으로도 표시되어야 하며, 오류·진행·복사 결과 같은 상태 변화는 화면 낭독기에 알려야 한다. 모든 클릭·터치 대상은 높이 44px 이상이고, 글자 대비는 일반 글자 4.5:1·큰 글자 3:1 이상이어야 한다. 움직임 감소 설정에서는 장식 애니메이션을 모두 멈추고 최종 상태를 보여야 한다.
- **FR-028**: 데스크톱(1440px 기준), 태블릿(1024px 기준), 모바일(390px 기준)에서 입력 → 결과 확인 → 복사 또는 인쇄 시나리오가 완료되어야 한다. 완료의 기준은 가로 스크롤이 없고(최소 360px 너비까지), 모든 행동 버튼이 화면 안에서 눌리며, 내용이 잘리지 않는 것이다. 구간은 데스크톱 1101px 이상, 태블릿 768~1100px, 모바일 767px 이하로 한다.

### Key Entities

- **구직자 프로필(입력)**: 한 번의 상담에서 입력되는 정보로, 학력(수준, 상태), 전공 목록, 경력 목록(직무명, 업종, 기간) 또는 경력 없음, 나이, 인턴 경험(있음/없음, 내용, 기간), 자격증 목록, 교육이수 목록(과정명, 기간), 강점 3개로 구성된다. 상담사가 저장을 실행하기 전에는 저장되지 않는다(FR-025).
- **추천 직업**: 직업명, 추천 근거(연결된 입력 항목 참조), 상담에서 함께 확인할 점(한 문장). 결과당 정확히 3개.
- **자기소개서 키워드**: 키워드, 연결된 강점, 연결된 추천 직업, 2~3문장 설명. 결과당 정확히 3개.
- **공통 안내문**: 모든 결과에 포함되는 참고용 안내 문구.
- **상담사 계정**: 로그인 주체. 본인의 구직자 기록과 상담 이력을 소유한다.
- **구직자 기록**: 한 구직자에 대한 기록 단위(이름, 선택적 연락처로 구분, FR-029). 한 상담사 계정에 속하며 여러 상담 이력을 가진다.
- **상담 이력**: 저장된 한 번의 상담으로, 구직자 프로필 입력, 생성 결과, 상담 일시를 포함한다. 구직자 기록에 연결될 수 있다.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 처음 사용하는 상담사가 표준 입력(경력 2개, 자격증 1개, 강점 3개 수준)을 입력하고 결과를 확인하기까지 결과 생성 대기 시간을 포함해 3분 이내에 완료할 수 있다.
- **SC-002**: 표시되는 모든 결과에서 추천 직업과 키워드가 각각 정확히 3개이다(100%).
- **SC-003**: 모든 추천 근거(직업 3개, 키워드 3개)가 실제 입력 항목을 하나 이상 참조한다(100%).
- **SC-004**: 결과에 검증되지 않은 수치(취업률, 연봉, 채용 공고 수 등)가 포함되지 않는다(0건).
- **SC-005**: 나이, 경력 공백, 이력 부재를 부정적 근거로 쓰는 문장이 없다. 신규 진입자, 경력 공백, 중장년 샘플 입력(`test-personas.md` P1~P3)을 각각 3회 이상 생성해 검토자 1명 이상이 읽은 결과에서 0건이다.
- **SC-006**: 입력 오류가 있을 때 오류 항목마다 수정 방법이 안내되며, 수정 후 입력 내용이 유지된다.
- **SC-007**: 결과 생성 실패 후 입력을 다시 하지 않고 재시도할 수 있다.
- **SC-008**: 시범 사용한 상담사의 대다수(목표 80% 이상)가 처음 사용해 안내 없이 결과 확인까지 도달한다.
- **SC-009**: 복사물과 인쇄물에 안내문이 항상 포함된다(100%).
- **SC-010**: 로그인하지 않은 사용자와 다른 상담사는 저장된 이력과 구직자 기록에 접근할 수 없다(접근 사례 0건).
- **SC-011**: 저장한 이력은 다시 열었을 때 저장 당시의 입력과 결과가 동일하게 표시된다(100%).
- **SC-012**: 삭제를 실행한 이력과 기록은 이후 어떤 화면에서도 조회되지 않는다.
- **SC-013**: `test-personas.md` P1~P5를 각각 3회 이상 생성한 결과를 검토자 1명 이상이 읽고, 모든 결과가 "구직자와 함께 봐도 괜찮다"고 판단된다(FR-019). 안내문 두 줄은 모든 결과에 있다.

## Assumptions

- 사용자는 한국어를 사용하며 결과도 한국어로 제공된다.
- 상담사가 대면 상담 중 구직자 정보를 대신 입력하며, 구직자는 결과 화면을 함께 본다.
- 나이는 만 나이 정수로 입력하며 허용 범위는 15~99세이다(FR-004).
- 경력 공백은 별도 입력 항목이 없다. 시스템은 기간 문자열을 해석해 공백을 계산하지 않으며, 상담사가 입력한 내용에서만 공백이 드러난다.
- 구현은 두 단계로 나눈다(사용자가 2026-10-11 분석 보고서의 권고에 따라 이 분리를 수용함). 1단계는 US1~US5와 FR-001~029, FR-036~041이고, 2단계는 US6~US8과 FR-030~035(로그인, 이력 저장, 구직자 기록)이다. 1단계에서는 아무것도 저장하지 않는다. 2단계 전에는 "상담 이력으로 저장"이 비활성으로 표시된다.
- 입력 이력은 결과 생성을 위해 외부 AI 서비스로 전송된다. 그 서비스의 데이터 보관·학습 정책이 소속 기관의 개인정보 방침과 맞는지는 기관이 확인한다(FR-039).
- 입력 한도는 FR-037을 따른다.
- 추천 직업은 구직자 이력과 강점에 기반한 일반적 참고 제안이며, 실제 채용 가능성은 보장하지 않는다.
- 상담사가 저장을 실행하지 않은 입력과 결과는 화면을 닫으면 사라진다.
- 로그인, 상담 이력 저장, 구직자 DB는 사용자 요청에 따라 범위 안이다. Constitution은 이를 반영해 v2.0.0으로 개정되었다(원칙 VI).
- 로그인 방식(계정 생성, 비밀번호 재설정 등)은 상담사 본인 확인이 되는 일반적 방식을 쓰며 구체 방식은 계획 단계에서 정한다.
- 구직자 식별 정보(이름, 연락처)를 저장하므로 개인정보 수집·보관에 대한 구직자 동의가 필요하다. 동의 확인은 구직자 기록 생성 시 상담사가 확인하는 항목으로 둔다.
- 상담사는 본인 소속 기관의 개인정보 처리 방침을 따르며, 구직자 동의 절차는 기관 운영 영역으로 본다.
- 직업명 기준은 FR-036을 따른다.
- 사용자 유형은 상담사 하나이며 관리자 등 별도 역할은 없다.
