# Contract: 복사 텍스트와 인쇄 형식

**Feature**: `001-job-recommendation-keywords` | **작성일**: 2026-10-11
**기준**: design 13.5, 13.7, 15절. spec clarify에서 보류했던 "복사·인쇄 형식"을 시안 기준으로 확정한 것이다(확정 승인은 사용자 확인 필요).
**원칙**: 복사물과 인쇄물에는 구직자 입력 정보(나이, 학력, 이력 원문 요약)를 넣지 않는다(design 6절, 15절). 단, 추천 근거 안의 연결 항목 문구(예: "전공: 사회복지학")는 결과의 일부이므로 포함한다.

## 1. 복사 텍스트 형식 (FR-021)

일반 텍스트(서식 없음)이며 줄바꿈과 번호만 쓴다. 복사에는 `navigator.clipboard.writeText`를 쓰고, 실패하면 "복사하지 못했어요. 결과를 직접 선택해 복사해 주세요."를 보인다(design 14절).

```
상담 참고 결과

※ 결과는 참고용이며, 상담사와 함께 검토해 활용합니다.
※ 입력하신 이력과의 적합도를 기준으로 한 결과이며, 채용 수요나 취업을 보장하지 않습니다.

A. 취업 가능성이 높은 추천 직업 3개

1. {title} ({subtitle})
   [표준 분류 확인 필요]                      ← isStandardName=false일 때만
   추천 근거: {rationale 문장들. needsConfirmation이면 "[확인 필요] " 접두}
   연결된 입력 항목: {label}: {value}, {label}: {value}
   상담에서 함께 확인할 점: {checkPoint. needsConfirmation이면 "[확인 필요] " 접두}

2. …
3. …

B. 자기소개서 키워드 3개

1. {keyword}
   연결 강점: {strengthText}
   연결 직업: {linkedJobTitle}
   연결된 입력 항목: {label}: {value}, …      ← strength 외 연결 항목이 있을 때만
   설명: {description 문장들}
   함께 이야기 나눠 볼 점: {mismatchNote}      ← mismatchNote가 있을 때만

2. …
3. …

[확인 필요] 표시가 붙은 문장은 상담에서 직접 확인이 필요한 내용입니다.
※ 결과는 참고용이며, 상담사와 함께 검토해 활용합니다.
※ 입력하신 이력과의 적합도를 기준으로 한 결과이며, 채용 수요나 취업을 보장하지 않습니다.
```

- 안내문 두 줄은 **맨 위와 맨 아래 모두** 넣는다(화면과 같은 위치, FR-016, SC-009).
- "[확인 필요] 표시가…" 줄은 결과 중 `needsConfirmation`이 하나라도 있을 때만 넣는다.
- 강점-이력 불일치 안내는 "함께 이야기 나눠 볼 점"이라는 **별도 항목**으로 유지한다(design 13.7).
- 복사 완료 문구: "결과를 복사했어요. 구직자 입력 정보는 포함되지 않아요."(`aria-live=polite`), 버튼 글자는 2.5초간 "✓ 복사했어요".

### 복사 텍스트 테스트 (Vitest)

| 테스트 | 기대 결과 |
|--------|-----------|
| 안내문 두 줄이 첫 부분과 끝 부분에 있다 | 통과 |
| 직업 3개와 키워드 3개의 번호가 모두 있다 | 통과 |
| `needsConfirmation` 문장에 `[확인 필요] ` 접두가 있다 | 통과 |
| `mismatchNote`가 있는 키워드만 "함께 이야기 나눠 볼 점" 줄이 있다 | 통과 |
| 키워드의 "연결된 입력 항목" 줄은 `strength` 외 연결 항목이 있을 때만 있다 | 통과 |
| 나이, 학력, "입력 정보 요약"의 항목명이 복사 텍스트에 없다 | 통과 |

## 2. 인쇄 형식 (FR-022)

별도 화면 없이 `/result`에 `@media print` 스타일을 적용하고 `window.print()`를 호출한다.

| 항목 | 값 | 근거 |
|------|----|------|
| 용지·여백 | A4, 여백 14mm (`@page`) | design 15절 |
| 글자 | 본문 9.5pt, 줄 간격 1.45 | design 15절 |
| 숨길 것 | Header, 상단 고정 안내 바, 행동 버튼 바, 상태 알림, 입력 정보 요약, 재생성 안내, 범례의 화면용 색 | design 15절 |
| 보일 것 | 제목 "상담 참고 결과"(굵은 밑줄) → 안내 상자(두 줄, 굵은 테두리) → A 영역(검은 바탕 흰 글자 제목) → 직업 3개 → B 영역(흰 바탕, 굵은 테두리, 왼쪽 두꺼운 선) → 키워드 3개 → 하단 안내문 + "[확인 필요]" 설명 | design 15절 |
| 항목 상자 | 1px 검은 테두리, 페이지 중간에서 끊기지 않음 (`break-inside: avoid`) | design 15절 |
| 라벨 | "근거 · ", "연결 항목 · ", "상담에서 함께 확인할 점 · "처럼 굵게 | design 15절 |
| 흑백 구분 | 배경색 없음. A/B는 채움/윤곽, "확인 필요"는 `[확인 필요]` 텍스트 + 왼쪽 이중선 + 이탤릭, 불일치 안내는 점선 구분선 + "함께 이야기 나눠 볼 점" 라벨 | design 15절 |
| 안내문 | 위(제목 아래)와 아래(하단) 모두 두 줄 | FR-016, SC-009 |
| 항목 포함 범위 | 포함: 제목, 안내문, 직업 3개와 키워드 3개의 모든 필드(근거, 연결 항목, 상담에서 함께 확인할 점, 연결 강점, 연결 직업, 설명, 함께 이야기 나눠 볼 점, "표준 분류 확인 필요" 표시), "[확인 필요]" 설명. 제외: 서비스 이름, 생성 일시, 구직자 입력 정보, 입력 폼 | FR-021, FR-022 (복사물도 같은 범위, 1절) |

- **A4 한 장 요구**: 직업 3개와 키워드 3개가 각 필드 한도(data-model 2.1)를 최대로 채워도 A4 한 장에 들어가도록 문장 길이 한도를 정했다. 한도를 모두 채운 최악 입력으로 PDF 페이지 수를 확인하는 테스트를 둔다. 한 장에 들어가지 않으면 문장 한도를 줄이거나(우선), 두 장 허용으로 spec을 바꾼다(사용자 결정). **확인 필요**: design 15절도 "A4 한 장 여부는 확인 필요"로 남아 있다.
- 인쇄 시 브라우저가 붙이는 머리글·바닥글(주소, 날짜)은 설정을 사용자가 정하며 코드로 끌 수 없다. 이 주소는 입력 내용을 포함하지 않는다(상태는 메모리, URL에 입력 없음).

### 인쇄 테스트 (Playwright)

| 테스트 | 기대 결과 |
|--------|-----------|
| `emulateMedia({ media: 'print' })` 후 Header, 버튼 바, 입력 요약이 보이지 않는다 | 통과 |
| print 미디어에서 안내문 두 줄이 위와 아래에 보인다 | 통과 |
| `page.pdf({ format: 'A4' })` 결과가 1쪽 (한도 최대 입력 기준) | 통과, 아니면 위 결정 필요 |
| 직업 3개, 키워드 3개 상자가 페이지 중간에서 끊기지 않는다 | 확인 필요: PDF 텍스트 위치로 점검 |
| 배경색 없이 구분되는지 | **수동 확인**(흑백 인쇄) |
