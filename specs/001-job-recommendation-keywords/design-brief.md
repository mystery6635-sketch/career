# Design Brief: 초기상담 도우미 (가칭) 메인 페이지

**Feature**: `001-job-recommendation-keywords` | **선택 시안**: A (신뢰감 있는 전문 도구) | **작성일**: 2026-10-10
**시안 위치**: Claude Design 프로젝트 "초기상담 도우미 메인 페이지 시안 (A/B)" → `시안 A - 전문 도구.dc.html`
**근거 문서**: `spec.md`, `.specify/memory/constitution.md` (원칙 XII, XIII, XIV 중심)

> 이 문서는 시안 A의 확정 방향과 남은 수정 사항을 정리한 것이다. 코드는 포함하지 않는다.
> 로컬 코드베이스에는 아직 구현이 없다.

## 1. 확정 사항과 가정

- 서비스 이름은 가칭 "초기상담 도우미"이다. 정식 이름이 정해지면 시안과 문서를 일괄 교체한다.
- 사용자: 상담사(주 사용자), 구직자(상담 중 화면을 함께 봄). 상담 현장에서 태블릿 사용을 고려한다.
- **가정**: Constitution은 아직 원칙 VI·XI 개정 전이다. 로그인과 상담 이력 저장은 명세상 범위 안이지만, 이 브리프의 메인 페이지에는 로그인 UI를 두지 않는다(요청 사항). 로그인 진입 위치는 별도 결정이 필요하다.
- 메인 페이지에는 spec.md에 없는 기능을 추가하지 않는다.

## 2. 디자인 목표

1. 상담사가 처음 보고 바로 "무엇을 하는 도구인지" 알 수 있다.
2. 전문 도구로서의 신뢰감을 주되, 구직자가 함께 봐도 위축되지 않는 부드러운 문구를 쓴다.
3. 이력 조각이 연결되어 직무로 이어진다는 서비스의 핵심 메시지를 시각으로 전달한다.
4. 데스크톱, 태블릿, 모바일에서 "상담 시작하기"까지 막힘 없이 도달한다.

## 3. 화면 구성 (시안 A 기준)

| 순서 | 영역 | 내용 |
|------|------|------|
| 1 | Header | 서비스 이름, "이용 방법" 링크. 로그인 영역 없음 |
| 2 | Hero | 메인 문구 "이력을 강점으로, 강점을 직무로.", 보조 문구, CTA 2개, 참고용 안내문, 오른쪽 시각 요소 |
| 3 | 이용 흐름 | 4단계: 구직자 정보 입력 → AI 분석 → 결과 확인 → 상담사와 함께 검토 |
| 4 | 상태 표시 | 배지 6종: 입력 중, 필수 항목 누락, 분석 중, 결과 준비됨, 확인 필요, 생성 실패 · 다시 시도 |
| 5 | 결과 미리보기 | 가상 데이터로 추천 직업 1개(근거 포함)와 키워드 1개(연결 강점, 설명). 수치 없음. 참고용 안내문 재표시 |
| 6 | Footer | 아래 "수정 사항" 1번 참고 |

**CTA**: 주 CTA "상담 시작하기"(입력 화면으로 이동), 보조 CTA "이용 방법 보기"(같은 페이지 이용 흐름으로 이동).
**참고용 안내문**: "결과는 참고용이며, 상담사와 함께 검토해 활용합니다." Hero와 미리보기 하단에 항상 표시한다(FR-016, 원칙 I).

## 4. 시각 방향

- **색**: 어두운 네이비 Hero, 네이비에서 틸·그린으로 이어지는 절제된 그라데이션, 민트 포인트, 본문 영역은 밝은 서페이스.
- **Hero 시각 요소**: 학력·경력·자격증·강점 카드 4장이 얇은 선으로 연결되어 추천 직업 카드 1장으로 모인다. 미세한 격자를 배경에 둔다.
- **타이포그래피**: IBM Plex Sans KR 한 가지. 단계 번호와 영문 라벨에만 모노스페이스. 본문 16px 이상.
- **형태**: 각진 작은 반경(4~6px). 과도한 Glassmorphism과 큰 둥근 카드는 쓰지 않는다.
- **모션**: 카드가 차례로 떠오르고 연결선의 점선이 흐른다. `prefers-reduced-motion` 설정에서는 모든 장식 애니메이션을 중지하고 최종 상태를 그대로 보여준다.

## 5. 반응형 기준

> **구간 정의 갱신**: 이 표의 구간(1024/640/639px)은 초기 브리프 기준이며 **design.md 21절의 구간(데스크톱 1101px 이상, 태블릿 768~1100px, 모바일 767px 이하)으로 대체되었다.** 구현은 design.md 21절을 따른다.

| 구간 | 기준 |
|------|------|
| 데스크톱 (1024px 이상) | Hero 2단(문구 + 시각 요소), 이용 흐름 4열 |
| 태블릿 (640~1023px) | Hero 1단, 시각 요소는 문구 아래 가운데, 이용 흐름 2열, 미리보기 1열 |
| 모바일 (639px 이하) | Hero 축약, CTA 두 개를 제목 바로 아래 전체 너비 세로 배치, 이력 조각 2×2 + "연결" 구분선 + 직업 카드, 이용 흐름은 세로 타임라인 |

- 360px 너비에서 가로 스크롤이 없어야 한다. 터치 대상은 44px 이상이다(원칙 XIV).

## 6. 접근성 기준 (원칙 XIII)

- 모든 링크와 버튼은 키보드로 접근 가능하고 포커스가 3px 이상의 선으로 보인다. "본문 바로가기" 링크를 둔다.
- 상태는 색상만으로 구분하지 않고 아이콘과 텍스트를 함께 쓴다.
- 본문 글자 대비는 WCAG AA(4.5:1) 이상, 큰 글자는 3:1 이상이다.
- 장식 요소는 보조 기술에서 제외하되, 같은 정보를 다른 영역에서 텍스트로 제공한다.

## 7. 만들지 않을 것

- 로그인·회원가입 버튼, 가격표, 기관·고객 로고, 후기 섹션
- 취업률, 연봉, 채용 공고 수 등 수치 강조 (원칙 IV)
- 특정 연령·성별을 연상시키는 인물 이미지 (원칙 V)
- 과도한 Glassmorphism, 흔한 AI 랜딩 페이지 연출
- spec.md에 없는 기능 (채용공고 연동, 공유 링크, 자소서 전문 작성 등)

## 8. 시안 A 수정 이력과 남은 사항

**기준 프로토타입**: Claude Design 프로젝트의 `시안 A - 서비스 프로토타입 v3.html` (원본과 v2는 보존).
**Constitution**: 2.0.0으로 개정되어 원칙 VI(통제된 저장)와 IV("취업 가능성이 높은" 표현 조건)가 바뀌었다.

v3에서 반영한 것:

1. 저장 안내 문구를 "저장하기를 누르기 전에는 저장되지 않습니다"로 바꾸고, 결과 화면에 "상담 이력으로 저장" 자리를 추가했다(시안에서는 동작하지 않음, FR-032).
2. 공통 안내문에 "이력과의 적합도 기준이며 채용 수요나 취업을 보장하지 않는다"를 추가했다. 화면, 복사물, 인쇄물에 모두 포함된다(FR-016).
3. 결과 제목을 "취업 가능성이 높은 추천 직업 3개"로 바꿨다(FR-012). 메인 보조 문구는 "잘 맞는 직업"을 유지한다.
4. "준비 상태"를 "상담에서 함께 확인할 점"으로 바꾸고 문장을 부드럽게 고쳤다.
5. 통용 직업명에 "표준 분류 확인 필요" 표시를 추가했다(FR-036).
6. 강점-이력 불일치 안내를 인쇄·복사에서도 별도 항목으로 유지한다.
7. 입력 한도를 FR-037에 맞췄다(강점 100자, 인턴 400자, 전공 6개, 경력·자격증·교육이수 20개). 나이는 15~99로 두고, 나이가 추천에 쓰이지 않는다는 안내를 추가했다.
8. 분석 지연(30초 후 안내)과 시간 초과(120초 후 중단) 상태를 추가했다(FR-023).
9. 태블릿 1024px에서 히어로가 한 열로 배치되도록 분기를 1100px로 올렸다.
10. 마지막 반복 행은 "비우기", 오류를 고치면 오류 요약 개수 갱신, 오류 요약 링크 높이 44px, 개인정보 안내 글자 확대, 연결선 애니메이션 3회 후 정지, 이모지 제거.

남은 사항 (렌더링으로 직접 확인 필요):

- 1440/1024/390px 레이아웃, A4 한 장 인쇄, 포커스 표시, 글자 대비.
- 정식 서비스 이름(가칭 "초기상담 도우미").
- 식별 정보·지시문 입력 경고 상태(FR-009, FR-010)는 시안에 없다.
- "요청 제한" 상태는 명세 요구사항이 없다. 명세에 추가하거나 실패 화면과 합칠지 결정한다.
- 비교용 시안 B는 선택되지 않았으므로 구현 대상이 아니다.

## 9. 평가 기준 (시안 확정 전 확인)

- 메인 문구와 CTA가 첫 화면에서 스크롤 없이 보이는가? (예/아니오)
- "상담 시작하기"가 한 번의 클릭 또는 탭으로 도달하는 주 행동으로 분명한가? (예/아니오)
- 참고용 안내문이 Hero와 미리보기 두 곳에서 보이는가? (예/아니오)
- 세 가지 화면 크기에서 가로 스크롤이나 잘림이 없는가? (예/아니오)
- 상태 배지 6종이 색상 없이도(흑백 기준) 구분되는가? (예/아니오)
- `prefers-reduced-motion` 설정에서 움직임이 모두 멈추는가? (예/아니오)
- 수치, 인물 이미지, 로그인 UI, 금지 요소가 없는가? (예/아니오)
